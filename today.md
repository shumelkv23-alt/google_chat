## Этап 0 — Подготовка → проверка: app стартует в batch-режиме

1. [ ] В `.env` на время теста:
   ```
   PROCESSING_MODE=batch
   BATCH_SIZE=5            # маленький, чтобы пачка собиралась быстро
   BATCH_TIMEOUT_SECONDS=60
   BATCH_POLL_SECONDS=10
   ```
2. [ ] Запустить `uvicorn app.main:app --reload` → в логах `batch_mode_enabled` +
   `batch_ticker_started`.

## Этап 1 — Контролируемый базовый прогон → проверка: пачка разобрана, вакансии созданы

Самый быстрый цикл — без HTTP/Google, прямой вызов флаша скриптом.

3. [ ] `python -m scripts.seed` — засеять 8 сообщений (лягут с `is_processed=false`).
4. [ ] Новый скрипт `scripts/run_batch.py` — разово зовёт `flush_due_batches()`
   (или `flush_batch(space)`), печатает итог. Запустить.
5. [ ] Проверка результата (SQL):
   - `chat_messages`: все seed → `is_processed=true`
   - `vacancies`: появились (питонист, тимлид, DevOps, фронт), мусор «как дела» — нет
   - `vacancy_revisions`: create/update/close по делу
   - В логах: `batch_due → batch_flushed (messages=8, actions=N)`

## Этап 2 — Сценарии по фичам → проверка: каждый ведёт себя по fork.md

6. [ ] **Семантика/группировка:** «питонист 300» + «подняли до 350» в одной пачке →
   ОДНА вакансия с update, не дубль (ядро гипотезы).
7. [ ] **Тред-привязка:** расширить seed сообщениями с общим `thread_id` → проверить,
   что follow-up привязался к вакансии треда.
8. [ ] **Цитата-привязка:** сообщение с `quoted_message_id` на другое в пачке →
   привязка по цитате (в логах/ревизиях).
9. [ ] **Онлайн-ветка:** при включённом app отправить reply в тред УЖЕ существующей
   вакансии → `batch_inline_resolved` сразу, не дожидаясь пачки.
10. [ ] **Edit:** правка сообщения, ещё ждущего пачку → `edit_queued_for_batch`
    (только текст); правка уже обработанного → полный `handle_edit`.
11. [ ] **Delete:** удалить сообщение из пачки до флаша → не попадает в пачку
    (`is_deleted` фильтр), вакансия не создаётся.
12. [ ] **Триггеры:** count (≥BATCH_SIZE → флаш сразу) и timeout (<BATCH_SIZE →
    флаш через BATCH_TIMEOUT_SECONDS).

## Критерии успеха дня

- Батч стартует, тикер флашит по обоим триггерам
- Базовый прогон: корректные вакансии, мусор отсеян, `is_processed` проставлен
- Группировка follow-up'ов внутри пачки работает (главное)
- Треды/цитаты/онлайн-ветка/edit/delete ведут себя по fork.md
- Нет регрессий: `pytest -q` остаётся зелёным

## Откат / очистка после тестов

- Вернуть `.env`: `PROCESSING_MODE=per_message` (и дефолтные batch-параметры)
- Подчистить seed: `DELETE FROM chat_messages WHERE message_id LIKE 'seed-%'`
  (+ связанные вакансии/ревизии, если мешают)
- Полный откат кода: `git checkout main`
